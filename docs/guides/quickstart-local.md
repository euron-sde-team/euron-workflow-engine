# Quickstart: run WorkflowEngine locally

Everything runs in Docker on your machine: Postgres, Valkey, the Floci AWS emulator, Mailpit,
the demo APIs, the API, two workers and the web app. No AWS account, no API key.

## Prerequisites

| Tool | Version | Used for |
| --- | --- | --- |
| Docker with Compose v2 | Docker 24+ | The whole stack (`make up`) |
| GNU Make | 3.81+ | Entry points |
| OpenSSL | any | `make env` generates local secrets |
| uv | 0.13+ | API tests and tools (optional for just running) |
| Node.js and pnpm | Node 22, pnpm 9 | Web tests, Playwright (optional for just running) |

Give Docker at least 4 GB of memory. The first `make up` builds both images, which takes a
few minutes.

## Start

```bash
make up      # builds the images, provisions Floci with Terraform, migrates, starts everything
make demo    # the Northwind Outfitters workspace with two weeks of real executions
```

`make up` prints the addresses when every service is healthy:

| Service | Address |
| --- | --- |
| Web app | http://localhost:3130 |
| API reference (Swagger UI) | http://localhost:8130/docs |
| Mailpit (every email the workflows send) | http://localhost:9130 |
| Demo APIs, Slack-style channels | http://localhost:9131/slack |
| Postgres | `localhost:5453` (user `wfe`, password `wfe`) |
| Valkey | `localhost:6413` |
| Floci (AWS emulator) | http://localhost:4613 |

`make demo` prints the demo accounts and the shared password (it is `WFE_DEMO_PASSWORD` in
`deploy/compose/.env`, generated by `make env`):

| Account | Role |
| --- | --- |
| `maya@northwind.example.com` | owner |
| `ravi@northwind.example.com` | editor |
| `lena@northwind.example.com` | viewer |

The seed is real, not fixtures: it signs and sends shop webhooks, publishes events and runs
the seven gallery templates through the engine against the demo APIs, Floci (S3, SQS, SES)
and a read-only warehouse database, then spreads the finished executions over the last two
weeks so the dashboard has a shape.

## Five minutes with the demo

1. **Dashboard.** Success rate, volume per day, the slowest workflows, recent failures,
   the queue and the workers.
2. **Workflows.** Open *Ship paid orders from the shop*. Click *Create shipment* to see
   its retry policy: the demo fulfillment API answers `503` to every first attempt.
3. **Executions.** Filter by *Failed*, open one: the graph shows where it stopped, the
   timeline shows each attempt, the step panel shows the input and the error.
4. **Dead letters.** Retry one: the execution resumes from the failed step.
5. **Mailpit and Slack.** Open http://localhost:9130 and http://localhost:9131/slack to
   see what the workflows sent.
6. **Send a webhook yourself.** The order workflow listens on a signed webhook:

   ```bash
   SECRET="whsec_$(printf '%s' "$(grep WFE_DEMO_PASSWORD deploy/compose/.env | cut -d= -f2):shop" | shasum -a 256 | cut -c1-32)"
   BODY='{"order_id":"SO-4242","customer":{"name":"Ines Moreau","email":"ines@trailhead.example.com","tier":"gold"},"items":[{"sku":"TENT-2P","title":"Two-person tent","qty":3,"price":249}],"total":747}'
   SIG="sha256=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac "$SECRET" | cut -d' ' -f2)"
   curl -s http://localhost:8130/hooks/northwind/shop/orders \
     -H "content-type: application/json" -H "x-shop-signature: $SIG" \
     -H "idempotency-key: order-4242" -d "$BODY"
   ```

   The answer carries the `execution_id`; open it under *Executions*. Send the same request
   again: the idempotency key returns the same execution instead of shipping twice.

## Stop

```bash
make down    # stops the stack and deletes its volumes (database, emulator state, Terraform state)
```
